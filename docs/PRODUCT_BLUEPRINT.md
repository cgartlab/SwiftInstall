# SwiftInstall 产品蓝图

> 从「批量安装器」升级为「设计驱动的换软件助手」。
> 本文件记录 2026-11 的战略收敛结论，作为后续开发的对齐基准。**变更时同步更新本文件。**

---

## 1. 一句话定位

**「换软件，不丢数据。」**
帮你找到更合适的软件，并基于**最新、已核对、标注版本**的资料，告诉你怎样安全地换过去——**给指导，不代办；一键装新版，由 sis 执行。**

- 面向：中文 Mac 用户先行（架构预留多语言），首发聚焦设计师/创意工作者。
- 形态：Mac 桌面 App（现代前端 + 动效）+ Go 引擎（复用 `sis` 作为执行层）。
- 与竞品的位置：Alternaut/AlternativeTo 只"推荐不落地"；Setapp 只"卖应用不做迁移"；`brew bundle` 只"装不推荐"。**我们补的是「发现 → 可信迁移指导 → 一键装新版」这条链，并用设计把它做得好用好看。**

---

## 2. 本轮关键决定（决策台账）

| # | 议题 | 决定 |
|---|------|------|
| 1 | 市场与语言 | 中文先行，架构从第一天做 i18n，可扩展海外 |
| 2 | 形态 | Mac 桌面 App（现代前端做动效）+ Go 引擎 |
| 3 | 迁移的深度 | **只做「AI 生成的最新、详细、准确的迁移指导」，明确标注日期与适用版本；不真正搬运用户数据** |
| 4 | 隐私边界 | 因不做数据迁移，App 不接触用户数据；AI 仅检索/生成公开知识，云调用只发"应用名+版本"，不发个人数据 |
| 5 | 开源策略 | `sis` 引擎继续开源（GPL）；消费级 App + 云端 AI 闭源 / SaaS（服务端隔离，规避 GPL 传染） |
| 6 | 成功定义 | 先验证 PMF：用户真的按指导换过去 + 愿反馈/纠错 + 有留存/自发传播；不急于收费 |

**第 3 条是本轮最重要的转向**：砍掉了"真实迁移"这一最重、最易翻车（数据丢失 = 信任归零）、隐私风险最高、且逐应用成本极高的部分。代价是**护城河与收费点随之转移**——见第 5、7 节。

## 3. 产品形态与五层架构

```
发现（AI + curated 平替库，免费）
   ↓ 对比（理由 / 价格 / 能力 / 隐私 / 来源）
   ↓ ★迁移 Playbook（最新 + 版本校验 + 可执行步骤 + 来源 + 社区纠错）★
   ↓ 一键安装新软件（sis 执行；卸载旧软件可选）
   ↓ 环境管理 / 软件栈健康（可持续复访）
   ↑
内容飞轮（"XX 换 YY 不丢数据"内容 = 获客 + Playbook 数据来源）
   ↑
社区 UGC（迁移后贡献/纠错 = 数据飞轮）
```

- **发现层**：免费，入口与传播点（对标 Alternaut 必须免费）。
- **迁移 Playbook 层**：差异化核心，见第 4 节。
- **执行层**：`sis` 一键装新版（已有的 homebrew/npm/github/winget 多后端）。
- **设计层**：整个体验的护城河，尤其"迁移向导/阅读"的画布。
- **社区层**：早期仅"迁移后贡献/纠错 Playbook"这一轻 UGC，不做论坛。

## 4. 核心资产：迁移 Playbook 数据模型

**Playbook 不是一段文字，而是"带版本校验、带可执行步骤、带来源、可被社区纠错"的结构化迁移手册。** 这是与"随便问 ChatGPT"拉开差距的关键。

```yaml
playbook:
  from: { app: Sketch,       versions: ["99.x", "100.x"] }
  to:   { app: Figma,        versions: ["latest"] }
  applies_to: { os: [macOS] }
  last_verified: 2026-11-05          # 人工核对日期（关键）
  verified_by: human | community | auto
  staleness: fresh | aging | stale   # 由管线自动计算（见第 5 节）
  confidence: high | medium | low
  data_fidelity:
    exports_cleanly: [文件、图层、组件]
    loses: [插件脚本、某些交互原型]
  steps:
    - title: 在 Sketch 导出
      detail: 具体菜单路径 + 注意事项
      source_url: 官方文档链接
    - title: 在 Figma 导入
      detail: ...
      source_url: ...
  sources: [官方帮助页, changelog, 版本说明]
  known_issues:
    - text: 99.x 以下字体映射异常
      reported_by: community
      date: 2026-11-01
```

**要点**：
- 每条 step 必须挂 `source_url`（可核验），否则降级为"未验证"。
- `last_verified` + `staleness` 是产品的信任基石：**用户一眼看到"这条指导是几号核对过的、适用于哪个版本"**——这正是通用 AI 给不了的东西。
- 用户可按 Playbook 逐步操作后回填"成功了/哪里不对"，形成社区纠错。

## 5. 新鲜度与可信度管线（这才是真护城河）

指南类产品最怕"过期/瞎编"。护城河 = **持续让指导保持最新、可核验**。建议半自动管线：

1. **AI 起草**：抓取官方帮助文档 / changelog / 版本说明，AI 生成初版 Playbook。
2. **人工核对**：人工确认步骤与 `data_fidelity`，打 `last_verified` 与 `confidence`。
3. **定期复检**：定时抓取 `sources` 页面，检测变更 → 自动标 `aging/stale`，提醒复核。
4. **社区纠错**：用户反馈错误/失效，进入复核队列，`verified_by: community`。
5. **覆盖率扩展**：按"用户需求量 + 数据可导出性"排序，逐对补齐。

> 这套"新鲜度管线"是运营工程 + 内容工程，不是一次性代码——**也是抄不走的慢资产**。AI 只是起草/复检的工具，不替代核对。

---

## 6. AI 与人工的分工边界

| 环节 | AI 负责 | 人工/社区负责 |
|------|---------|---------------|
| 发现/平替 | 自然语言理解、候选生成、理由撰写 | 平替库事实核对 |
| Playbook | 起草步骤、抓取来源、复检变更 | 核对准确性、标注版本与日期 |
| 排错 | 解析用户描述、给一般性建议 | 沉淀为 `known_issues` |
| **绝不** | 直接搬运/改写用户数据 | — |

## 7. 商业模式（免费什么，收什么钱）

**Playbook 本身接近免费（ChatGPT 也能给），所以不靠它收费。** 收费点在它周边：

| 层 | 免费 | 付费 |
|---|---|---|
| 发现 / 平替推荐 | ✅ | — |
| 迁移 Playbook（基础） | ✅ 大部分 | 长尾/新版本优先覆盖（Pro） |
| 环境管理 / 软件栈健康 / 更新提醒 | 基础 | **Pro 订阅 $8–15/月**（Raycast / Setapp 锚） |
| 我的软件栈云同步 + 变更通知 | — | Pro |
| 团队软件审计 / 换软件 Playbook（B2B） | — | 按项目/按人 |
| 推荐返佣 | — | 需**明示**，否则毁信任 |

- **核心收入 = Pro 订阅（环境管理 + 云端软件栈 + 持续更新）**，B2B 团队迁移手册为辅。
- 发现与 Playbook 是**获客与留存漏斗**，不是收银台；收银台是"把整套软件管起来"的持续服务。

## 8. 北极星指标与验证（3–6 个月）

因不再代办迁移，"完成真实迁移"改为可衡量的替代指标：

1. **采用率**：看过 Playbook 的用户中，完成"安装新软件"动作的比例。
2. **成功反馈**：用户回填"换成功了"的数量（核心信号）。
3. **社区贡献**：纠错 / 新增 Playbook / 分享软件栈的用户数。
4. **留存与传播**：次周回访率、自发分享率。

**PMF 信号**：≥ N 次"用户按 Playbook 成功换并反馈"，且出现**自发**的纠错/贡献 —— 即证明"有人真的愿意换、换得成、且愿意参与"。

## 9. 三阶段路线图

**阶段 0 · 体验验证（先做）**
- 产出"发现 → Playbook → 一键装新版"的**高保真动效交互原型**（可点，体现设计优势）。
- 目的：先让人"看到"换软件可以这么安心好看，收集反馈。

**阶段 1 · 可行性 MVP**
- 跑通 1 对真实 Playbook 的完整内容 + 引擎一键安装目标软件。
- 建立 Playbook 数据结构 + 半自动起草/复检管线雏形。
- 首批覆盖：设计工具（Sketch→Figma、Adobe→Affinity）与笔记（Notion→Obsidian）中先选 1 类打样。

**阶段 2 · 产品化**
- 多 Playbook + 社区纠错 + 环境管理（Pro）+ 云同步。
- 内容飞轮上线（"XX 换 YY 不丢数据"系列）。

---

## 10. 待定事项与风险

**待定**
- 首批打样优先级：设计工具（你的 niche、高价值）vs 笔记（搜索量最大）——需定。
- 指南维护模式：纯人工 vs 半自动抓取+人工复核——建议半自动，需评估工作量。
- 桌面壳技术选型：Wails（Go 原生、复用现有技能）vs Tauri（生态更好）——阶段 0 前定。

**风险**
- **弱护城河风险**：仅"AI 写指南"会被 ChatGPT 替代 → 必须靠**新鲜度 + 来源核验 + 版本标注 + 社区纠错 + 嵌入操作现场**建立防御。
- **转化风险**：只给指导=用户仍要自己动手，换软件摩擦仍在 → 靠"一键装新版"+ 可执行步骤降低一半摩擦，并用指标盯"真的换了没"。
- **数据过时风险**：应用版本更新快 → 必须建复检管线，否则信任崩塌。
- **scope 风险**：从 CLI → 消费 App + 内容 + 社区，是家公司级工程量 → 严厉分阶段，先体验后产品。
