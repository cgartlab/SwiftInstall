# SwiftInstall 交互体验与样式 · 设计方案

> 目标：在"交互体验 + 样式"上做出**竞品没有的差异化**，而不是再做一版"更漂亮的卡片列表"。
> 依据 2026 年一手设计趋势调研 + 我们的产品立场（免费/开源策展 + 迁移指导 + 体检）。

## 一、市场与交互模式调研（摘要）

- **动效即品牌语言（2026）**：微交互、弹簧物理、编排好的状态过渡成为产品"手感"的主层；仍是"加动画=打磨"的产品会显得过时。但 ~35% 用户有动效敏感，`prefers-reduced-motion` 是**硬性底线**（[Creative Alive, 2026](https://creativealive.com/micro-interactions-2026-motion-ux-rules/)）。
- **动效预算要花在"低频、仪式感"处，常用处要克制**：Raycast 命令面板几乎不做开合动画，因为它一天被调用上百次；把"动画预算"留给你很少到访的第一次体验（[Kane Small](https://www.kanesmall.com/writing/subtlety-of-animations)）。
- **时长/缓动要有刻度**：Linear 大多 200–350ms、hover 100–150ms，签名曲线 `ease-out-expo`；拖拽用弹簧、跟随手势速度（[DesignMD](https://www.designmd.co/blog/motion-systems-how-ai-products-animate)）。
- **两阶段漏斗：探索 ≠ 评估**。探索用宽目录/卡片帮用户建立词汇；评估阶段只保留"改变决策的证据"，别把 50 张卡再倒一遍（[Two-Stage AI Tool Discovery](https://dev.to/derek_fowler_tech/designing-a-two-stage-ai-tool-discovery-funnel-5hb5)）。
- **渐进披露 + 一次点击到"啊哈"**：把"看到价值"的动作压到一步，再逐层露出进阶（Litmus 试用改造 Day0 使用率 75%→92%；Qonto 发现卡转化 17.6%）。
- **对比用"滑动揭示"**：Dub 的 slide-to-compare —— 拖动滑块揭示前后差异，比并排两列更直观（[60fps.design](https://60fps.design/appsites/dub-slide-to-compare-interaction)）。
- **键盘优先 + 两级动作**：Raycast `↵` 执行默认动作、`⌘K` 展开次级动作面板（[BuiltUX](https://builtux.com/raycast-command-bar-ux-keyboard-first-navigation-2026/)）。
- **Mac 桌面八趋势**：空间层次、半透明材质、情境化主题、动态字体、有目的的微交互、触感反馈、数据密集布局、键盘优先（[Transmission Apps, 2026](https://transmissionapps.com/industry-insights/emerging-design-trends-software-interfaces/)）。

**对我们的启示**：竞品（Bundl/Packd/Setapp）都在做"卡片目录 + 一键装"。我们要赢，不能拼目录规模，要在**"发现→评估→换过去"的交互**上做出记忆点，并把动效花在低频仪式（首次体检、第一次换软件）。

## 二、设计原则（本产品的四条铁律）

1. **动效预算分级**：常用高频处（列表滚动、hover、命令面板开合）→ 100–150ms、近乎无感；低频仪式（首次体检、平替决策、迁移完成）→ 可到 300–500ms、允许编排。
2. **两阶段，不混屏**：`探索`（清单/分类浏览）与 `评估`（逐条决策）分开；评估页只留"改变决策的证据"（价格、免费版够不够、数据能否带走）。
3. **键盘是平等的**：所有核心动作都有键盘路径；列表 + 命令面板（`↵` 默认、`⌘K` 次级）。
4. **可访问即底线**：`prefers-reduced-motion` 有 crossfade/直切变体；对比度达标；焦点可见；触控目标 ≥ 44px。

## 三、三个"签名交互"（差异化核心）

### ① 体检仪式（Scan → Report 的形变过渡）——低频、可重动效
- 首次启动：一枚"标本身"式的环形扫描器，沿网格逐格点亮，计数上涨；扫描完成时**整块扫描器在 500ms 内"摊开"成报告页**（scan 环 → 报告统计卡，共用位置做 shared-element 过渡）。
- 为什么值得重做：这是用户**第一次**看到产品能力，一次仪式感胜过十处 hover。
- 约束：之后每次体检（高频）只做 200ms 的轻过渡，不重复仪式。

### ② 平替滑卡 Swap Deck —— 我们的招牌（评估阶段）
把"体检发现的平替项"做成一副**可拖拽的卡牌堆**（已在 `docs/prototype/swap-cards.html` 做出可点原型）：
- 一张卡 = "你现在的（琥珀·付费）→ 更好的（绿·开源/免费）" + 一句"为什么换"。
- **拖拽**：卡片跟手、轻微倾斜；松手按位移/速度决定 → 右滑"换"、左滑"留"；飞出的卡片用**弹簧**回弹下一张。
- **翻面**（点击/Enter）：3D 翻到背面，显示"数据保真 + 迁移第一步 + 来源"，把"评估证据"就放在决策点。
- 计数 "已选换 N / 已保留 M"，一键"把这批存成安装清单"。
- 价值：把"看清单"变成"做决定"，比静态列表胜出；也是社交传播点（截图/录屏好看）。
- 键盘：`←` 留、`→` 换、`Enter` 详情、`Z` 撤销。

### ③ Slide-to-Compare 对比 —— 单条"换"的决策证据
在单条替换详情里，用**拖拽滑块**揭示"现在的 vs 平替"（左侧现在的截图/维度，右侧平替），而非两列并排：
- 手指/鼠标拖动中央把手左右移动，两层等高对齐，差异（价格、开源、免费版范围、可导出性）实时显形。
- 适合"差一点就想换"的犹豫时刻，降低理解成本。

**辅助**：迁移 Playbook 做成**可勾选的分步轨**（progress rail），完成一步打勾、可"复制这一步命令"，全程只读不代办。

## 四、样式方向（在《Cabinet of Equivalents》上再进一步）

保持既有品牌（骨纸/铁墨/氧化绿/焦琥珀 + 中文衬线标题），但补三点"层次与手感"：

- **运动 token**：`--dur-1:120ms`（hover）、`--dur-2:200ms`（常规）、`--dur-3:320ms`（模态/抽屉）、`--dur-4:520ms`（首次仪式）；缓动主力 `cubic-bezier(.22,.61,.36,1)`（ease-out-expo 近似），拖拽用弹簧（stiffness≈300, damping≈30）。
- **克制的空间层次**：卡片/抽屉用 1px 暖色描边 + 极淡暖阴影（非里层灰影）；仅"正在决策的卡片"抬升一层；不做满屏玻璃拟态。
- **动态字体**：数字用 tabular-nums（统计、计数、倒计时）；标题衬线、正文无衬线、代码等宽，三级清晰。
- **数据密集但可读**：清单像"账本"，行高一致、发丝线分隔；靠层级而非装饰。

**要避免的"AI 生成感"**：满屏圆角卡片 + 同款灰影、每个区块都 fade-up、单一词高亮、`A · B · C` 串、无意义编号 01/02/03。我们的编号只用于"真的是步骤"的迁移轨。

## 五、可访问性与性能红线

- `prefers-reduced-motion: reduce` → 所有编排动效降级为 120ms crossfade 或直切；滑卡改为按钮"换/留"。
- 键盘可达：卡片可 Tab 聚焦，`Enter/Space` 翻转，方向键决策；焦点环 2px 绿、offset 2。
- 对比度 ≥ 4.5:1（正文）；触控目标 ≥ 44px；拖拽同时提供按钮等价操作。
- 性能：只动 `transform/opacity`；拖拽用 `requestAnimationFrame`；不阻塞主线程。

## 七、一句话差异化

竞品让你"看清单、点安装"；我们让你**"翻一张卡，就跟一件旧软件体面告别，并知道数据怎么带走"**——把免费的发现、可信的核验、安全的迁移，做成有手感的一件事。

## 八、竞品交互拆解（2026-11 补充调研）

| 产品 | 值得注意的交互 | 对我们的机会 |
|---|---|---|
| **Setapp** | Collections + 每个集合**「Install all」**；AI 搜索 + AI 助手；分类/子分类**多选筛选**；查看截图可用**方向键翻页** | 我们有"清单"，可给每份清单加**「整份安装」**入口（已用"设为安装清单"承接）；AI 已具备（`explain`） |
| **CaskHub** | 精选货架 + 轮换 Hero + **Top Charts（真实安装数据）** + Recently added；`⌘F` 即时搜索；一键装/升/卸带进度；adopt 已装应用 | 我们做**版本核验/迁移**这类它没有的深度；不做"应用商店"式广度 |
| **Bundl** | **成对对比页**（Raycast vs Alfred）+ Collections + AI Builder 生成一条命令 | 我们的 **`/swap` 平替滑卡**比"对比页"更进一步：把"看"变成"逐条决策" |
| **Ninite** | 勾选 → 一个安装器；极简 | 我们多了发现/核验/迁移，Ninite 只有"装" |
| **Raycast Store** | 两级动作（`↵` 默认 / `⌘K` 次级）；命令面板几乎无开合动画 | 主 GUI 后续加 `⌘K` 命令面板；高频处克制动效 |

**结论**：竞品在"目录广度 + 一键装"上领先；我们在**"可信策展 × 版本核验 × 迁移指导 × 有手感的决策交互"**这条组合上领先。继续深挖后者，不去卷目录规模。

## 九、设计语言升级：Liquid Glass 与「三 Z 平面」

参考 Apple Liquid Glass（macOS 26）与桌面八趋势（[Apple HIG · Materials](https://developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass.md)、[Transmission Apps](https://transmissionapps.com/industry-insights/emerging-design-trends-software-interfaces/)）：

- **三 Z 平面预算**：① 后层＝窗口 chrome/侧栏；② 中层＝内容面（清单/卡片/账本）；③ 前层＝浮层（抽屉、命令面板、拖拽代理、滑卡）。
  - **新组件必须认领已有平面，不新开第四层**；阴影按平面统一（而非逐组件拍脑袋）。
- **半透明只用于控制/导航层**（顶栏、抽屉、浮动按钮）；内容层用标准材质。我们保持《Cabinet》骨纸为主，只在**顶栏/抽屉/滑卡悬浮**用极轻的半透明，避免满屏玻璃感。
- **降低透明度兜底**：每个半透明面都要有 `prefers-reduced-transparency`（或对比度设置）下的**实心替代**；文字在"最差背景"（纯白/高饱和壁纸）上仍 ≥4.5:1。
- **动效时长收敛**：常规 120–180ms；面板/抽屉 240ms；首次仪式 520ms。**高频展开不用 overshoot 弹簧**（连按会"卡在反弹里"，见 Transmissions 的教训）——用可中断、无过冲的曲线。

## 十、交互规格细化（可执行）

**A. 对比（签名交互 #3）：文字维度默认并排，滑块仅用于“截图前后对比”（本轮原型 `docs/prototype/compare.html`）**

> 判断：研究明确提示“并排更清楚时不要用滑块”。规格表是文字，用**并排两列**最清晰；只有“同一画面的前后截图”才用滑块揭示。我们把这一条写进规范，避免为了炫技牺牲可读性。

- 用**真实的 `input[type=range]`** 当控件（键盘 ←/→/Home/End 天然可用、可被读屏识别），视觉把手只是装饰。
- 揭示用 `clip-path: inset()` **裁剪而不是缩放**（避免每次 pointermove 重排重采样、拖拽发卡）。
- 把手**可视细、热区 ≥44px**；点击把手或图片区都能拖；**两端常驻标签**（现在的 / 平替），不让用户靠记忆分左右。
- 拖到边界要夹紧（0–100%）；`prefers-reduced-motion` 去掉把手"呼吸/入场"等装饰，保留控件行为。

**B. Swap Deck（已落地 `/swap`）**：拖拽用弹簧跟随手势速度；松手按位移/速度判定；翻面显示"数据保真+第一步+来源"；`Z` 撤销；reduced-motion 降级为按钮"换/留"。

**C. 体检 Scan→Report**：首次用 shared-element 让扫描环"摊开"成报告统计（520ms、一次）；之后每次体检只 200ms 轻过渡，不重复仪式。

## 十一、交付前自查（无障碍 × 最差背景）

- [ ] 每个动效都有 reduced-motion 变体；每个半透明面都有"降低透明度/高对比"的实心兜底。
- [ ] 正文对比度在最差背景上 ≥4.5:1；焦点环 2px、可见；触控目标 ≥44px。
- [ ] 滑块/滑卡同时提供**按钮等价操作**；键盘可达、可读屏。
- [ ] 只动 `transform/opacity/clip-path`；拖拽走 rAF；不阻塞主线程。
